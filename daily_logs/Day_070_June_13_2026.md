## Appendix B -- The persistence layer failure mode, formally

The Pack 220 wired-state persistence shipped Day 65 had a control-flow gap that wiped the entire cognition layer on every save/load roundtrip from Pack 225 (vs_fsm shipped Day 67) through Pack 246 (Day 70). The failure mode was:

1. `_PERSIST_ATTRS` enumerated 20 cognition module attributes (`fe / curiosity / tom / re / vsa / belief / verifier / proof_gen / schema / crystal / persona_proj / meta_mirror / imp_lattice / cf / cwm / schema_refiner / self_mod_refiner / goals / world / moe / dssc`). Each was pickled wholesale via `pickle.dumps(obj)`.
2. `vs_fsm` was ABSENT from this tuple. The Pack 225 / 226 / 227 / 228 ship sequence added vs_fsm to the organism but never updated `_PERSIST_ATTRS`. The schemas, emergent_pos, _emergent_pos_clusters, _isa_inverse, transition_count, schema_transitions, abstracted_count, skipped fields all survived in-memory training and silently vanished on save.
3. Direct addition of `vs_fsm` to `_PERSIST_ATTRS` was not viable because `VSFiniteStateMachine.__init__` stores back-references `self.org = organism` and `self.mr = organism.unified`. Pickling vs_fsm with these back-references would have recursively pickled the entire organism, which contains the substrate, which contains the bridge, which contains references back to the organism. Pickle cycle.
4. `multirole_memory.MultiRoleMemory` had Pack 199 `_bigram_count` (the surprise gate state) but `save_ikg` only serialized `unigram_count`. The `_bigram_count` dict was silently empty on every load.
5. `IkigaiOrganism.load_ikg` parsed all the saved state but never instantiated the Pack 217 bridge classes `_wm_sys / _cg / _ec / _cas`. These four classes only initialized via lazy property access on first attribute reference. Code paths that didn't access the property would see None.

The diagnostic chain:

```
Pack 245F audit on organism.ikg:
  vs_fsm.transition_count = 0   (despite 9631 trained in Pack 246c memory)
  vs_fsm.schemas = 0              (despite 10 induced)
  vs_fsm._emergent_pos = {}       (despite 651 labeled)
  _bigram_count = {}              (despite Pack 199 surprise gate tracking)
  org._wm_sys, _cg, _ec, _cas: None
```

The Pack 246b fix:

```python

    'schemas', '_emergent_pos', '_emergent_pos_clusters',
    '_isa_inverse', 'transition_count', 'schema_transitions',
    'abstracted_count', 'skipped',
)

# In _gather_wired_state:
vs_fsm = getattr(self, '_vs_fsm', None)
if vs_fsm is not None:
    vs_state = {k: getattr(vs_fsm, k, None)
                  for k in self._PERSIST_VS_FSM_KEYS}
    out['_vs_fsm_state'] = pickle.dumps(vs_state)

# In _apply_wired_state:
if attr == '_vs_fsm_state':
    vs_state = pickle.loads(blob)
    fsm = self.vs_fsm   # triggers property -> lazy init with org/mr refs
    for k, v in vs_state.items():
        if v is not None:
            setattr(fsm, k, v)
    continue

# In multirole_memory.save_ikg npz:
bigram_prev=bg_prev, bigram_curr=bg_curr, bigram_vals=bg_vals,
bigram_total=np.int64(self._bigram_total),

# In multirole_memory.load_ikg:
if 'bigram_prev' in z.files:
    mr._bigram_count = {(str(p), str(c)): int(v)

# In integrate.py load_ikg (after _apply_wired_state):
br = self.bridge
```
