## 3. Pack 287.5 v2 -- Subword Aggregation (Japan/Tokyo Fire=0.000 Closed)

The Pack 287.5 v1 KL fire signal keyed the teacher distribution on the first generated position's top-N tokens. DeepSeek-R1-Distill tokenizes "tokyo" as the subword chain " to" + "ky" + "o" across positions 0-2; the position-0 top token is the subword " to", which never matches the substrate's atomic action token 'tokyo'. The KL blew up and fire collapsed to 0.000.

Three changes shipped v2:

1. **serve.py multi-position logprobs.** `_serialize_logprobs` truncated to `positions[:1]`. It now ships up to `_LOGPROB_MAX_POS = 24` positions (answers are short; max_tokens <= 128). Backward-compatible: callers reading `positions[0]` still get the first-token distribution. This required a 3090 redeploy -- serve.py has no hot-reload (scp to `/workspace/3090/serve.py`, Ctrl-C and re-run in terminal 1; the cloudflared tunnel in terminal 2 reconnects to port 8001). Verified live: the `/batch` endpoint returns 12 positions for "capital of Japan", chain " to"+"ky"+"o".

2. **Char-span greedy-chain reassembly.** New `_atomic_logprob_dist(positions, answer)` in `cat4_dopamine.py` takes the greedy token per position (entry[0], valid since the oracle runs temperature=0), concatenates the lowercased strings, locates the parsed answer word inside the concatenation, and SUMS the logprobs of the positions whose characters compose it -> the joint logprob of the whole atomic word. " to"(-0.636) + "ky"(0.0) + "o"(-0.119) -> P('tokyo') = 0.47. Degrades gracefully: single-position payloads (older serve.py) return the first-token distribution unchanged; reassembly misses fall back to the position-0 greedy token.

3. **KL fire clamp.** A partial teacher distribution (top-N, missing mass goes to "other") against a delta substrate (cache fast path) can drive KL negative. `_kl_fire` now clamps `kl = max(kl, 0.0)` so fire stays in [0, 1] and v1 fire <= v0 fire as designed.

A fourth fix fell out of the live probe: R1 now blurts the one-word answer, then a blank line, then reverts to a CoT ramble ("tokyo\n\nOkay, so I need to figure out...") that max_tokens truncates. The "last salient word" parser grabbed the ramble's tail. `_parse_answer` now keeps only the first non-empty line; single-line restated forms ("Greece's capital is Athens") are unaffected.

Gates: offline reassembly unit 6/6 (two-subword, cased+space, whole-word, restated, single-position back-compat, miss-fallback); live 6/6 capitals (tokyo/cairo/oslo/canberra all multi-subword, atomic in the distribution); Japan v1 fire **0.000 -> 1.0000**; recall bench 16/16. ## 4. Pack 291.8 -- Substrate-Native ⋆-Inverse Division (Invention 1 Closed)

Pack 291.7 handled division by encoding the Python-computed quotient `left // right` -- correct output, but not substrate-native. Kymn et al. 2023 §4.1.3 defines exact division through the modular multiplicative inverse.

Derivation. In the RHC encoding, dimension j of value x carries residue `u_j * x mod m` (u_j the integer multiplier per dim). For exact division q = x1 / x2 (x1 = q * x2):

```
u_j * q = u_j * (x1 * x2^{-1}) = u_j * r * s^{-1}   (mod m)
   where r = u_j * x1, s = u_j * x2, s^{-1} the modular inverse of s.
```

A modulus is VALID iff x2 != 0 mod m; when m divides x2 the residue field has no inverse (the gcd(x2, m) != 1 case). That modulus is dropped and q is CRT-recovered from the remaining valid moduli -- exact whenever the product of valid moduli exceeds q. This dissolves the "multi-valued / canonical-representative" concern flagged at the Day 77 close: the invertible moduli give one answer, and CRT closes it.

Shipped in `residue_hdc.py`: `div_factored` (per-dim `final_r = u_j * r * s^{-1} mod m`, drops moduli where x2 == 0 mod m), `div_int` (CRT over valid moduli only), plus `_modinv_vec` and `_residue_of` helpers. Wired into `math_eval.py`: exact division (b | a) routes to `rhc.div_int` (substrate-native, `dbg['substrate_native'] = True`); inexact division keeps the Pack 291.7 floor fallback (flag False). The math path is gated by the Pack 283 compositional classifier (see Pack 296, §9, for why that gate became load-bearing).

Gates: standalone unit (`day78_pack291p8_div_smoke.py`) -- plain exact divisions, single and double modulus-drop (35/7 drops m=7; 1001/77 drops m=7,11), 8-moduli set, 30 random mul/div round-trips, zero/inexact guards, all pass. Bench (`day78_pack291p8_bench.py`) -- 8 division probes (6 exact substrate-native + 2 inexact fallback) + 30/30 regression, all green. Code-only, no save (RHC is computed fresh per query).

**Invention 1 (HPE / RHC) is now fully closed:** add (Hadamard), sub (Hadamard.conj), mul (Kymn ⋆ §4.1.2), div (⋆-inverse §4.1.3) -- all four operations substrate-native at d=400, zero hardcoded lexicon.

## 5. Pack 293 -- Multi-Hop Compositional Reasoning (Native)

The first compositional reasoning in the organism, and native in `reason()` by default. Two question templates: yes/no ("is the capital of X in Y") and continent-answer ("what continent is the capital of X in").

The join is genuine, not a template trick. Hop 1 is an ordinary single-hop `reason("what is the capital of <X>")` -> capital; hop 2 is `reason("what continent is <capital> in")` -> continent, keyed on hop 1's output; the yes/no comes from comparing the continent to the question's target. Hops run with `do_multihop=False` (recursion guard) -- the substrate-composition join is a chain of cache lookups, exactly the roadmap's "HV unbind + re-bind across cache lookups," realized at the text-anchor level.

Method priority became: arith -> multihop -> single-hop ICL -> planner -> next_token. A composite query has no single cache anchor of its own, so without this path it fell to next_token garbage.

Intermediate facts (hop 2) were bootstrapped Pack-273-style: 21 continent-of-capital entries keyed on the resolved capital (paris -> europe, tokyo -> asia, ...), cache-only via `populate_cache_from_text`, no substrate write. Cache 837 -> 879. The bootstrap script spot-checks all 21 hop-2 anchors resolve before saving and aborts otherwise. organism.ikg saved 182.5 MB, backup `organism.ikg.bak_pre_pack293_20260621_131437`.

Gate: 10/10 multi-hop (every one via `method='multihop'`) + 30/30 regression. Follow-ups noted: continents are cache-only (not teacher-dopamine-hardened like capitals in Pack 276); a true HV-space unbind/re-bind join (vs text re-tokenization between hops) is the deeper version.

## 6. Pack 292 -- Knowledge-Graph Extraction (Organism Builds Its Own KG)

The organism now builds its own knowledge graph from the teacher. The insight that made it cheap: a triple (entity, attribute, value) maps exactly onto the existing queryable cache form -- "what is the <attribute> of <entity>" -> <value> -- so an extracted triple is absorbed straight into the anchor-action cache, is immediately answerable via `reason()`, AND is composable via Pack 293 multi-hop. The KG is the cache, phrased as questions. No new substrate primitive.

New module `ikigai/cognition/kg_extract.py` (`KGExtractor`). Pipeline: prompt the teacher for "attribute | value" lines (R1 actually emits "- attribute: value"); the parser accepts colon or pipe, strips bullets/numbering, rejects list/sentence values (more than 4 tokens or containing commas -- R1 dumps essay-length "famous works" lists), drops leading filler ("approximately"), and rejects degenerate echoes; absorb the canonical query phrasings via `populate_cache_from_text`.

A no-save smoke over France/Japan/Brazil returned 23/23 recall (7 essay-lists correctly rejected), confirming parse quality before any persistence. The bootstrap then ran 51 entities -> 387 triples, cache 879 -> 1613 (+734), extract wall 277 s (51 sequential teacher calls). The persistence used gate-before-save: KG recall sample 12/12 + 30/30 + multi-hop 10/10 all verified BEFORE `save_ikg`, so a bad teacher answer cannot overwrite a known capital. organism.ikg saved 182.5 MB, backup `organism.ikg.bak_pre_pack292_20260621_133825`.

Teacher-data quirks (not pipeline bugs): Norway/New Zealand parsed thin (+0/+1 triples), "prime minister of United States -> biden". ## 7. Pack 294 -- Active Learning (Native + Wired Live)

The organism self-teaches online. When it is not confident on a fact query it asks the teacher, absorbs the answer into the cache, and answers -- so the next identical query is a native cache hit. It gets smarter as it is used.

`general_reasoner.reason()` gained `do_active=True`, `enable_active_learning(oracle, lo, hi)`, and `_active_learn` / `_active_learn_eligible` / `_looks_like_question`. The loop, after the Pack 296 hardening (§9): a confident answer = an EXACT Pack-273 cache hit (the `icl_exact_cache` flag, not a similarity threshold) -> free, no teacher; everything non-exact and atomic and fact-shaped -> ask the oracle, absorb, answer (and set `icl_action` = learned). Method priority: arith -> multihop -> confident b_self_icl -> active_learn -> low-conf b_self_icl -> planner -> next_token.

Pollution guards: `is_atomic_query` (skip math) + `_looks_like_question` (fact-shape). Hops run `do_active=False` so multi-hop stays pure. The path is INERT until an oracle is attached (class-attr default `_al_on=False`), so benches and normal loads never trigger surprise teacher calls.

Wired live in `integrate.py`: the `general_reasoner` property auto-calls a new `IkigaiOrganism.enable_active_learning(url, lo, hi)` when the env var `NEUROSEED_TEACHER_URL` is set (opt-in, mirroring `NEUROSEED_LMDB_CACHE`). Verified: no env -> al_on=False (benches inert); env set -> al_on=True, and the novel query "what is the capital of Mongolia" self-taught to "ulaanbaatar" through the runtime with zero manual calls.

Gate (`day78_pack294_active_learn_smoke.py`): 3/3 novel facts learn-then-native (Iceland/Nepal/Kazakhstan: first call active_learn, repeat call b_self_icl), AL-off baseline does not learn, and 30/30 with active learning ON makes **0 teacher calls** on confident queries (no spam). Code-only, no save (online; learned facts persist on the next save_ikg).

## 9. The Three Production-Path Bugs Pack 296 Surfaced

The benchmark started at 62%, and the misses were not what they looked like. Direct probing showed the teacher's raw answers were correct (" au", " mars", " 0"); the organism was answering with substrate garbage instead of asking. Three real bugs in `general_reasoner.reason()`, each fixed and regression-clean (30/30 + 10 multi-hop + active-learning no-spam after all three):

1. **Arithmetic false-fire (the big one).** `substrate_arith` fabricated a degenerate "add" on plain word queries -- "which planet is known as the red planet" returned `pred=12 op=add`, "chemical symbol for gold" returned `11`, "romeo and juliet" returned `9`. The word->magnitude operand recall happily decodes a magnitude for words like "red" and "planet", and arith is priority #1, so it ate the query before active learning could run. Fix: gate the arithmetic path with the Pack 283 `is_compositional_query` classifier (which is exactly what it is for). Only real arithmetic now engages. This is a production correctness win beyond the benchmark -- the organism no longer hallucinates math on word questions.

2. **Active-learning false-confidence.** After the Pack 292 KG bootstrap densified the "what is the X of Y" template in the substrate, novel queries of that shape produced soft `recall_action` similarities of ~0.7-1.0 against the dense KG anchors -- indistinguishable from a real cache hit by any threshold. The first fix (raise the confidence threshold to 0.999) was insufficient; some false matches reach ~1.0. The correct fix: trust ONLY the exact Pack-273 cache hit (the deterministic anchor hash), tracked by a new `icl_exact_cache` flag. Confident = exact hit; everything else defers to the teacher. Capitals are exact hits (sim=1.0), so 30/30 is unaffected.

3. **Numeric answers dropped.** `TeacherOracle._WORD_RE` was letters-only, so "0" (freezing point of water) parsed to None and fell through to substrate garbage. Added digits to the pattern.

With all three fixed the benchmark went 62% -> 68% -> 85%. The arithmetic-gate fix in particular hardened the whole `reason()` routing.

## 10. Pack 285.6 v0 -- SBC-Bound Substrate Foundation

The Pack 285 v0 SBC encoder broke the d=400 discrimination ceiling but stayed a research primitive for two reasons: noise-brittleness and a binding mismatch. Pack 285.6 v0 fixes the binding -- the documented blocker -- and proves the cleanup-wall bypass.

The bug: SBC `bind` was Hadamard product (`a * b`). SBC vectors are sparse (one active slot per block of L); two of them share a slot only by chance, so the Hadamard product zeros every mismatched block and binding recovers nothing. The module docstring already prescribed the correct operation -- per-block slot-index addition mod L, the group operation on Z_L^B. Shipped in `sparse_block_codes.py`: `bind_tuple` / `unbind_tuple` / `encode_tuple` and instance `bind` / `unbind`; the old Hadamard kept as `bind_hadamard` (deprecated) for the regression that exposed it.

Benchmark (`day78_pack285p6_sbc_bench.py`, pure numpy, no organism load -- the module is research-only and off the production recall path, so 30/30 is untouched):

```
1. binding correctness (200 pairs)
   slot-add bind/unbind recover : 200/200 = 100%
   Hadamard bind/unbind recover :   0/200 =   0%  (the bug)

2. cleanup at N items     SBC acc / us       FHRR acc / us
   N=100                  100% /  81.3       100% /   170.3
   N=1000                 100% /  80.5       100% /  2100.4
   N=10000                100% /  80.9       100% / 19298.3

3. bound key->value over 10k vocab : 300/300 = 100%  (472 us per op)
```

The win is precise: SBC cleanup is O(d) argmax-per-block, CONSTANT in vocabulary N (~81 us at N=100 and at N=10,000), and exact; FHRR cosine-against-codebook cleanup is O(N*d) and slows linearly (~240x slower at N=10k). This is the cleanup-wall bypass stated correctly -- cleanup cost is flat in vocabulary, not bounded by it.

Code-only, no save. The full flip -- a parallel cat-4 write path (FHRR + SBC-bound action HVs), cleanup routing through SBC when the bound HV is SBC-shape, doubling substrate cost ~40 MB, with a 30/30 gate and save -- is deferred to **Pack 285.7**, where the still-open noise-brittleness (100% at sigma=0, 0% at sigma>=0.5) will be handled via per-block redundancy/voting. Exact binds, as benchmarked here, are unaffected by noise.

## 12. Researcher Q&A: Cache Capacity And The Road To Long-Form

Two conceptual questions framed the day's stopping point and are recorded here for the program narrative.

**On the 45 GB / 1B-fact cache vs a model's parameters.** The substrate (the engine) is fixed at 192 MB and does not grow with facts -- it superposes them. The cache (the notebook) grows at ~44 B/fact: 1 billion facts = 44 GB on SSD, ~5 MB resident. The two are different storage classes: a transformer smears facts into its weights (lossy, frozen, hallucinating), while the cache stores them exactly, editably, and effectively unbounded on disk. By the ~2-bits-of-fact-per-parameter rule (Allen-Zhu & Li 2024), 1B exact facts is roughly the factual capacity of a ~10-15B parameter model -- but stored exactly instead of lossily, on disk instead of in VRAM, with the actual intelligence engine still 192 MB. The scorecard: on memory the organism already wins (exact, editable, cheap); on fluency/generation the transformer wins today.

**On long-form output.** This is the biggest remaining gap and was framed honestly with no calendar promise. The ladder: facts + exact composition (now) -> broader knowledge (292/294) -> a generation loop with grammar-bank enforcement (not yet built, the big lift) -> coherence layers for long spans -> scale. Fluent paragraphs appear only after the generation loop and coherence layers, which are many packs out. Foundation first, in order, no rush.
